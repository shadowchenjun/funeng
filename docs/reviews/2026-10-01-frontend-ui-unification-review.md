# 前台 UI 统一执行计划 Review

审查对象：`docs/plans/2026-10-01-frontend-ui-unification.md`，设计规范 r2，以及对应实现。核对分支 `feat/ui-unification`，HEAD `0e1cbb3`（U5）。日期：2026-10-01，北京时间。

## 结论

**需要修改后再验收。** 地基先行、共享组件、主题接管及分视图迁移的安排合理，当前静态门禁通过；发现 2 项功能风险及 1 项验收证据缺口。无已确认 P0/P1。此次不修改业务实现，也不发布应用。

## Findings

### R1 [P2] 页面缓存的验收忽略跨页面数据失效

- 计划位置：`docs/plans/2026-10-01-frontend-ui-unification.md:36`，将产品→分类→产品的“0 个 API 请求”作为通过条件。
- 实现证据：`frontend/src/App.vue:109`、`:137` 缓存 ProductsView/CategoriesView/DashboardView，key 只有 route.path。ProductsView 在 `:239` 仅 onMounted 拉取商品/分类，CategoriesView 在 `:170` 仅 onMounted 拉取分类计数，DashboardView 在 `:160` 仅 onMounted 拉取看板。没有 onActivated 刷新、共享数据版本失效或会话缓存重置。各页写入成功仅刷新自己的本地数据。
- 影响：访问过产品页后，在分类页添加分类再返回产品页，下拉分类不会包含新分类；访问过分类/看板后新增或删除商品，返回时分类产品数/看板统计仍是旧值。产品页也没有独立刷新分类字典的操作，需要硬刷新。缓存启用属于可观察的数据加载行为变化，不能仅以“不请求”判断无回归。
- 复现步骤：打开产品→打开分类并新增一类→返回产品→打开添加产品的分类选择器；另测打开分类/看板→到产品新增或删除→返回原页面。此项依据当前代码与生命周期路径确认，本次未在浏览器写入生产业务数据。
- 建议：保留筛选与分页等界面状态，用共享版本/dirty 标记、TTL 或 onActivated 刷新关联数据；退出/换账号时重置页面缓存。将无数据变化的缓存命中与有数据变化的刷新分别验收。
- 验收条件：新增分类立即可选，产品增删同步反映在分类计数/看板，切换账号不会沿用上一会话的数据缓存；无数据变化时可保留缓存。

### R2 [P2] “地图只有一个实例”不能证明快速切换时路线正确

- 计划位置：`docs/plans/2026-10-01-frontend-ui-unification.md:103`、`:106`，复用地图并以实例数/尺寸验收。
- 实现证据：`frontend/src/views/ColdChain.vue:892` 复用同一个 transportMap 并 clearMap；`:943`、`:953` await 地理编码；之后直接向共享地图写覆盖物，`:1026` 写 transportData。`onTransportSelectChange` 在 `:1092` 每次触发异步重画，缺少请求序号/当前选择校验与取消保护。
- 已复现：对当前函数原文进行 TypeScript 转译，在受控 AMap SDK stub 中选择 A→B，让 B 请求先完成、A 后完成。结果 selectedTransport=B，而 displayedTimeline=[A-start,A-end]；同一个地图留下 A、B 两条路线的标记，实例数仍然为 1。
- 证据：`docs/reviews/2026-10-01-ui-map-race-repro.cjs`，在仓库根目录运行 `node docs/reviews/2026-10-01-ui-map-race-repro.cjs`。脚本出口成功表示复现了已知缺陷，不代表该功能测试通过。它是源代码异步控制流复现，不是实际高德地图渲染验收。
- 建议：每次重画递增 generation，捕获地图实例/选择 ID；每个 await 后及最终提交前校验仍是最新请求且组件未卸载。先完成坐标计算，再一次性替换覆盖物和时间线，避免逐步写入已失效请求。
- 验收条件：慢网下 A→B→A 快速切换，选择器、轨迹、当前位置和时间线始终一致；切页/卸载后迟到回调不写已销毁实例；保留地图实例数/尺寸检查。

### R3 [P2] 最终验收缺少可复查的前端证据与关键交互矩阵

- 计划位置：`docs/plans/2026-10-01-frontend-ui-unification.md:140`–`:154` 为全量通过结论，`:162` 测试自评 7/10。文档只描述 headless Chrome 结果，没有测试脚本路径、截图位置、命令、账号角色、数据基线或结果文件。
- 实际门禁：frontend/package.json 没有前端测试命令；agent-lint 执行类型检查、后端 pytest、色值/emoji 等静态规则。258 项后端测试不能验证 KeepAlive 关联数据刷新、地图异步竞争、抽屉及弹窗行为。仓库 docs 中可见的大屏截图属于另一项农业原型任务，不能作为此次 UI 统一的前后对比证据。
- 缺口：仅列 1440/1200/390px，未列 768/769/1199px 的边界及普通用户/管理员；未覆盖 API 空数据、失败、离线地图、快速切换与跨页 CRUD。原计划明确在 SQLite 副本上测试，不能据此认定生产 Supabase 空表页面或线上版本已经验收。
- 建议：保存浏览器脚本或逐步检查清单、至少关键页面的前后截图、网络/控制台结果及 commit/数据集信息；按风险补 R1/R2 的交互回归，并记录空态/错误态、角色、断点边界。质量规范要求核心路径覆盖证据，自评分数不能替代实际覆盖率或明确的验收矩阵。
- 验收条件：独立审查者可按路径与步骤复现；新缺陷对应的前端回归失败→修复后通过；视觉和生产验收分开记状态。
